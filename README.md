# CallGuard 실험 앱 사용설명서

보이스피싱 **개입 시나리오(S1~S10)** 를 통제된 조건에서 하나씩 실행·측정하기 위한 연구용 Android 앱과 서버입니다.
연구자가 통화 중 아무 때나 원하는 개입을 강제로 발동시키고, 그 반응을 관찰·기록합니다.

> 이 프로젝트는 실서비스 앱(`2026-voice-fraud-intervention-main`)과 **별개인 독립 프로젝트**입니다. 실험용 임시 로직과 실서비스 로직이 섞이지 않도록 분리했습니다.

## 1. 전체 그림 — 4개 구성 요소

실험은 아래 4개가 **같은 서버 · 같은 방 코드**로 연결되어 돌아갑니다.

```
   [공격자 브라우저]              [연구자 콘솔 브라우저]
    client.html                  admin-dashboard.html
   (피싱 대사 타이핑)            (시나리오 발동·초기화·모니터링)
        │  ws:8080                        │  ws:8081
        └───────────┐        ┌────────────┘
                    ▼        ▼
              ┌─────────────────────┐
              │   PC: Node 서버      │  8080 시그널링 / 8081 모니터링
              └─────────────────────┘
                         │ ws:8080 / 8081
                         ▼
              ┌─────────────────────┐
              │  안드로이드 실험 앱   │  ← 참가자(피해자)가 드는 폰
              │  (참가자 화면)        │
              └─────────────────────┘
```

| 역할 | 무엇 | 실행 위치 |
|---|---|---|
| **서버** | 시그널링(8080) + 모니터링(8081) 중계 | 연구자 PC (Node.js) |
| **참가자(피해자)** | 실험 앱 — 일반 전화앱처럼 보임 | 안드로이드 **실기기** |
| **공격자** | `client.html` — 피싱 대사를 타이핑하면 참가자 폰에서 음성(TTS)으로 재생 | 아무 브라우저 |
| **연구자 콘솔** | `admin-dashboard.html` — 시나리오 무장·개입 실행·초기화·실시간 모니터링 | 연구자 PC 브라우저 |

> **왜 공격자가 타이핑?** 참가자 발화는 STT로 인식하지만, 공격자 대사까지 음성인식에 맡기면 오인식이 실험을 망칩니다. 그래서 공격자는 대사를 타이핑해 보내고, 참가자 폰에서 음성으로 재생됩니다.

## 3. 최초 1회 설정

### 3-1. 서버 의존성 (이미 있으면 생략)
```powershell
cd callguard-experiment\server
npm install
```

### 3-2. 방화벽 개방 (Windows)
`server\setup-firewall.bat` 를 **마우스 우클릭 → 관리자 권한으로 실행**.
→ TCP 8080·8081을 개방합니다. 폰 핫스팟 같은 공용 네트워크에서 폰이 PC 서버에 접속하려면 필수입니다.

### 3-3. 안드로이드 SDK 경로
`local.properties` 의 `sdk.dir` 가 본인 PC의 Android SDK 경로인지 확인하세요.
(`local.properties`는 깃에 포함되지 않으므로, 없으면 Android Studio로 프로젝트를 한 번 열면 자동 생성됩니다.)

### 3-4. ⭐ Vosk 음성모델 설치 (필수 — 없으면 빌드/음성인식 불가)
음성인식 모델(약 253MB)은 용량이 커서(파일 하나가 174MB로 GitHub 100MB 한도 초과) **깃에 포함하지 않습니다.**
아래 중 한 방법으로 모델을 직접 넣어야 앱이 동작합니다.

**방법 A. 표준 모델 내려받기 (권장)**
1. https://alphacephei.com/vosk/models 에서 **`vosk-model-small-ko-0.22.zip`** 다운로드
2. 압축을 풀면 나오는 폴더 **내용물**을 아래 경로에 넣습니다(폴더 이름은 반드시 `model-ko`):
   ```
   callguard-experiment/app/src/main/assets/model-ko/
   ```
   → 이 폴더 안에 `am/`, `graph/`, `ivector/`, `conf/` 등이 바로 보여야 합니다.

**방법 B. 실서비스 앱에서 복사**
메인 저장소(`2026-voice-fraud-intervention`)를 이미 받았다면 동일 모델이 있습니다. 그대로 복사:
```powershell
Copy-Item -Recurse "<메인저장소>\app\src\main\assets\model-ko" "callguard-experiment\app\src\main\assets\model-ko"
```

> 넣은 뒤 경로가 `app/src/main/assets/model-ko/am/final.mdl` 처럼 되어 있으면 정상입니다.

## 4. 실행 순서 (매 실험마다)

### ① 서버 실행 (PC)
```powershell
cd callguard-experiment\server
node signaling-server.js
```
실행되면 아래처럼 **접속 가능한 IP 목록**이 출력됩니다. 이 중 **폰이 붙어 있는 네트워크의 IP**를 기억하세요.
```
앱 서버 주소 입력:  ws://172.20.10.2  ← 아이폰 핫스팟
```
> ⚠️ `192.168.56.1` / `172.28.144.1` 같은 값은 VirtualBox·WSL 등 **가상 어댑터**라 폰에서 접속이 안 됩니다. 실제로 폰과 같은 네트워크의 IP를 고르세요.

### ② 안드로이드 앱 설치·실행 (폰)
폰을 USB로 연결 후:
```powershell
cd callguard-experiment
.\gradlew installDebug
```
또는 Android Studio에서 이 폴더를 열고 ▶ 실행. (앱 이름/패키지 `com.example.callguard.experiment` — 실서비스 앱과 따로 설치됨)

앱 첫 화면에서 입력:
- **서버 주소**: `ws://172.20.10.2` (①에서 고른 IP)
- **방 코드**: 예 `room-1234`
- **[통화 시작]** 탭

### ③ 공격자 브라우저 열기 (`server/client.html`)
- **IP**: `172.20.10.2` , **방 코드**: `room-1234` (앱과 동일)
- 연결 후 피싱 대사를 타이핑해 전송 → 참가자 폰에서 음성으로 재생

### ④ 연구자 콘솔 열기 (`server/admin-dashboard.html`)
- **서버 IP** + **같은 방 코드** 입력 → **[모니터링 시작]**
- "실험 기기 상태"에 **연결됨** 이 뜨면 준비 완료

> **핵심:** ②③④의 **방 코드는 반드시 동일**해야 하고, IP는 모두 ①에서 고른 같은 값이어야 합니다.

## 5. 실험 진행 방법

한 통화 안에서 시나리오를 **하나씩 순서대로** 실행합니다. 각 시나리오마다:

```
① 시나리오 무장 (예: S1 선택)
        ↓
② (공격자 대사 전송 / 필요 시 발화 강제 주입)
        ↓
③ "지금 개입 실행" 클릭  → 개입(차단·안내·설문)이 발동
        ↓
④ 참가자 반응 관찰 · 관찰 메모 기록
        ↓
⑤ 🔄 초기화  → 다음 시나리오를 위해 상태 리셋 (통화는 유지)
        ↓
   다음 시나리오 무장(S2) …
```

- **개입 발동은 두 가지 경로**가 있고 결과는 동일합니다:
  - **수동**: 콘솔의 "지금 개입 실행" 버튼 (원하는 타이밍에 정확히)
  - **자동**: 공격자 발화 위험도가 올라가면 무장된 시나리오가 자동 발동
- **🔄 초기화** 는 앞 시나리오에서 쌓인 위험도·마이크 차단·설문·배너를 모두 리셋해, 다음 시나리오가 깨끗한 상태로 시작하게 합니다. **매 시나리오 사이에 반드시 누르세요.**
- **S10(통화 강제 종료)** 은 발동하면 통화가 끊깁니다. 앱에서 다시 [통화 시작] → 공격자 재접속으로 새 통화를 시작하면 됩니다(정상 동작).

## 7. 연구자 콘솔 / 온디바이스 패널 기능

### 연구자 콘솔 (`admin-dashboard.html`) — 정식 실험용 (권장)
탭: **실시간 모니터 / 로그 / 연구자 콘솔**. 연구자 콘솔 탭의 조작 섹션:

| 섹션 | 기능 |
|---|---|
| ① 시나리오 선택 (무장) | S1~S10 중 하나를 기기에 무장 |
| ② 개입 실행 / 세션 제어 | **지금 개입 실행** · **🔄 초기화** · 통화 종료 |
| ③ 발화 강제 주입 (STT 우회) | 피해자/공격자 발화를 대신 주입 (숫자 프리셋, 요구+숫자 콤보 포함) |
| ④ 설문 수동 응답 | STT 인식 실패 시 연구자가 예/아니오 대신 기록 |
| ⑤ 관찰 메모 | 관찰 항목(경고 인지/계속 대답/대답 멈춤 등) 원클릭 기록 |
| ⑥ 기능별 간단 설문 | 각 시나리오 종료 후 5개 평가 항목을 예/아니오로 기록 |

> 연구자 콘솔은 참가자 폰 화면을 건드리지 않으므로 실험 타당성을 해치지 않습니다.

### 온디바이스 숨김 패널 — 노트북 없이 단독 테스트용
참가자 화면 **우측 상단 모서리를 5번 연속 탭** 하면 열립니다. 콘솔과 동일한 6개 섹션(무장/개입/초기화/발화주입/설문/관찰메모)을 제공합니다.

## 11. 문제 해결 (Troubleshooting)

**서버가 `EADDRINUSE: address already in use :::8080` 로 죽어요**
이전 서버가 아직 떠 있는 겁니다. 해당 프로세스만 정리 후 재실행:
```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```
> 서버를 끌 땐 실행 중인 터미널에서 `Ctrl+C` 로 종료하면 잔여 프로세스가 안 남습니다.

**폰이 서버에 연결이 안 돼요**
- IP를 잘못 골랐을 수 있습니다. 폰 브라우저로 `http://<서버IP>:8080` 접속해 확인 페이지가 뜨는지 확인하세요.
- 가상 어댑터 IP(`192.168.56.1` 등) 말고, 폰과 같은 네트워크의 IP를 쓰세요.
- 확인 페이지가 안 뜨면 `setup-firewall.bat` 를 관리자 권한으로 다시 실행하세요.
- PC와 폰이 정말 같은 Wi-Fi/핫스팟인지 확인하세요.

**세 화면이 연결됐는데 통화가 안 붙어요**
→ 앱·공격자·콘솔의 **방 코드가 완전히 동일**한지 확인하세요.

**AI 안내 음성이 안 들려요**
→ 폰에 **한국어 TTS 음성**이 설치돼 있는지, 스피커폰이 켜져 있는지 확인하세요.

**개입이 발동을 안 해요**
→ 먼저 시나리오를 **무장(①)** 했는지 확인하세요. 무장 안 하면 발화·트리거해도 아무 일도 없습니다.
