# CallGuard 사용설명서

`test_callguard` 브랜치에 커밋된 기능을 기준으로 작성되었습니다. CallGuard는 통화 중 보이스피싱 발화를 실시간으로 감지해 마이크/상대방 음성을 차단하고, 사용자에게 상황 확인 설문을 진행하는 Android 앱과 그 실험을 위한 로컬 서버/도구 모음입니다.

## 1. 구성 요소

| 구성 요소 | 위치 | 역할 |
|---|---|---|
| CallGuard 앱 | `app/` | 실시간 STT + 피싱 키워드 감지 + 개인정보 유출 감지 + 자동 개입(마이크 차단, 경고, 음성 설문) |
| 시그널링/모니터링 서버 | `server/signaling-server.js` | 두 기기 간 P2P(WebRTC) 통화 연결 중계(포트 8080) + 실시간 모니터링·세션 로그 저장(포트 8081) |
| 관리자 대시보드 | `server/admin-dashboard.html` | PC 브라우저에서 진행 중인 통화를 실시간으로 관찰하고 세션 로그를 확인하는 도구 |
| 테스트 클라이언트 | `server/client.html` | 실물 상대 기기 없이 PC 브라우저를 "상대방(공격자 역)" 삼아 통화 테스트를 할 수 있는 도구 |

모든 통신은 **같은 사설 네트워크(Wi-Fi) 안에서만** 이뤄지도록 설계되어 있습니다. 인터넷에 공개된 서버로 사용하지 마세요(아래 8. 주의사항 참고).

## 2. 사전 준비

### 2-1. 서버 실행
```bash
cd server
npm install        # 최초 1회
node signaling-server.js
```
정상 실행되면 아래처럼 출력됩니다.
```
CallGuard 시그널링 서버 실행 중 → ws://localhost:8080
CallGuard 모니터링 서버 실행 중 → ws://localhost:8081
```
- 포트 `8080`: 통화 연결(시그널링)
- 포트 `8081`: 실시간 모니터링 + 세션 로그(`server/logs/*.json`에 자동 저장, git에는 포함되지 않음)

### 2-2. 서버를 실행 중인 PC의 로컬 IP 확인
Windows 명령 프롬프트에서 `ipconfig` 실행 후 IPv4 주소를 확인합니다 (예: `192.168.0.10`). 앱과 브라우저 도구 모두 이 IP로 서버에 접속합니다.

### 2-3. Android 앱 설치
Android Studio로 `app/` 모듈을 빌드해 테스트 기기에 설치하거나, `./gradlew assembleDebug`로 빌드된 APK를 설치합니다. 최초 실행 시 한국어 음성 모델(Vosk) 로딩에 1~2분 정도 걸릴 수 있습니다(화면 하단 로딩 배너로 안내됨).

> 실험에 사용하는 모든 기기(앱을 설치한 스마트폰, 서버를 실행하는 PC, 브라우저로 접속하는 기기)는 **동일한 Wi-Fi**에 연결되어 있어야 합니다.

## 3. 혼자서 테스트하기 — 루프백 모드

두 번째 기기나 서버 없이도 감지·개입 로직만 빠르게 확인할 수 있습니다.

1. 앱 실행 후 첫 화면(다이얼 화면) 하단 **"시뮬레이션 도구"** 카드를 확인합니다.
2. 아래 3가지 버튼으로 원하는 상황을 바로 재현할 수 있습니다.
   - **상대방 발화 (피싱 감지 테스트)**: 검찰/금융감독원/가족 납치/택배 사칭 등 프리셋 문구를 누르면 상대방이 그 말을 한 것처럼 감지 파이프라인에 주입됩니다. 위험도가 누적되어 일정 키워드 수 이상이면 자동으로 경고 또는 차단됩니다.
   - **요구 직후 숫자 발화 콤보**: "주민등록번호 뒤 7자리까지 말씀해 주세요" → (1.5초 뒤) "901231 1234567" 처럼, 공격자가 정보를 요구한 직후 사용자가 숫자로 답하는 상황을 재현해 즉시 차단 로직을 테스트합니다.
   - **내 발화 (즉시 차단 테스트)**: "제 비밀번호는 1234입니다"처럼 사용자가 직접 개인정보를 말하는 상황을 재현합니다.
3. 하단 입력창에 원하는 문장을 직접 입력해 "내 발화 주입"도 가능합니다.
4. 아무 버튼이나 누르면 자동으로 루프백 통화가 시작되고, 곧이어 개입(경고 배너 또는 차단+설문)이 화면에 나타납니다.

`서버 주소`를 입력한 상태에서 루프백을 실행하면, 해당 서버의 모니터링 포트(8081)로도 이벤트가 전송되어 관리자 대시보드에서 같이 관찰할 수 있습니다.

## 4. 두 기기로 실제 통화 테스트하기 (P2P)

1. 두 기기 모두 앱을 실행하고, 다이얼 화면의 **"인터넷 통화(P2P)"** 카드에 다음을 입력합니다.
   - **서버 주소**: `ws://192.168.0.10` 형태(포트는 자동으로 `:8080`이 붙습니다). IP는 서버를 실행 중인 PC의 로컬 IP.
   - **방 코드**: 두 기기에서 **완전히 동일한 문자열**을 입력해야 같은 방으로 연결됩니다(대소문자·공백·특수문자까지 정확히 일치해야 함).
2. 먼저 입장한 기기가 `caller`, 나중에 입장한 기기가 `callee` 역할을 자동으로 부여받고, 두 번째 기기가 들어오는 순간 통화가 시작됩니다.
3. 한쪽에서 "공격자 대본" 프리셋 버튼을 누르거나 실제로 말하면, 상대 기기의 감지 파이프라인이 이를 분석합니다.
4. 통화 중 위험 발화가 감지되면 마이크/상대 음성이 자동 차단되고 설문이 시작됩니다(6장 참고).

## 5. PC 브라우저를 "공격자 역할"로 사용하기 (`server/client.html`)

실제 두 번째 스마트폰이 없어도, PC 브라우저를 상대방 기기처럼 써서 실험할 수 있습니다.

1. 브라우저에서 `server/client.html` 파일을 엽니다(더블클릭하거나, `npx serve server`처럼 정적 서버로 띄워도 됩니다).
2. **서버 IP**, **방 코드**를 스마트폰 앱과 동일하게 입력하고 **"방 입장"**을 누릅니다.
3. **"공격자"** 버튼 옆 입력창에 대사를 입력하고 Enter(또는 버튼 클릭)하면, 그 텍스트가 상대 기기(스마트폰)에서 실제 음성 인식 결과처럼 처리되고 TTS 음성으로 재생됩니다. 실제 마이크로 말하지 않아도 정확한 대본으로 테스트할 수 있는 기능입니다.
4. 마이크 권한을 허용하면 실제 음성 통화도 가능하지만, 실험 목적상 위 텍스트 입력 방식이 더 재현 가능성이 높습니다.

## 6. 개입(자동 차단) 동작 방식

감지된 위험도에 따라 두 단계로 다르게 반응합니다.

- **SUSPICIOUS(의심)**: 통화를 막지 않고 화면에 경고 배너만 표시합니다. 사용자가 배너를 확인(dismiss)하면 사라집니다.
- **SCAM(확정) / 개인정보 발화 감지**: 마이크와 상대방 음성을 즉시 차단하고, 진동 + TTS 경고("주의! 개인정보 유출 위험이 감지되었습니다...")를 재생한 뒤 **음성 설문**을 시작합니다.
  1. "전화를 건 사람이 본인이 직접 아는 분인가요?" (예/아니오)
  2. "가족이나 지인과의 실제 상황인가요?" (예/아니오)
  - 답변은 마이크로 "예/아니오" 계열 단어를 말하면 STT로 자동 인식됩니다.
  - 15초 동안 응답이 없으면 재촉 메시지가 나오고, 2회 연속 무응답이면 안전을 위해 통화를 자동 종료합니다.
  - 두 질문에 모두 답하면 설문이 종료되고 상위 로직이 통화 재개 여부를 결정합니다.

## 7. 실시간 모니터링 (`server/admin-dashboard.html`)

1. PC 브라우저에서 `server/admin-dashboard.html`을 엽니다.
2. 상단 입력창에 **서버 IP**와 **방 코드**(테스트 중인 통화와 동일한 값)를 입력하고 **"연결"**을 누릅니다.
3. **📡 실시간 모니터** 탭
   - 좌측: 양쪽 화자의 STT 결과가 말풍선으로 실시간 표시됩니다.
   - 우측: 현재 위험도(SAFE/SUSPICIOUS/SCAM)와 매칭된 키워드, 개입/설문/사용자 행동 이벤트 로그가 표시됩니다.
4. **📋 세션 로그** 탭: 통화가 진행되면서 쌓인 탐지 내역, 설문 응답, 종료 사유 등을 시간순 타임라인과 표 형태로 확인할 수 있습니다. 같은 방으로 다시 접속(새로고침 포함)해도 서버가 마지막 세션 로그를 다시 보내줍니다.

세션이 종료되면(`call_ended`) 서버가 해당 로그를 `server/logs/<방코드>_<타임스탬프>.json`으로 자동 저장합니다. 이 로그 파일들은 실험 결과 데이터이므로 `.gitignore`에 의해 git에는 올라가지 않습니다 — 별도로 백업이 필요하면 직접 복사해 두세요.

## 8. 주의사항

- 시그널링 서버(8080)와 모니터링 서버(8081)는 **별도 인증이 없습니다.** 반드시 신뢰할 수 있는 사설 네트워크(집/연구실 Wi-Fi)에서만 실행하고, 공인 IP·포트포워딩으로 외부에 노출하지 마세요.
- 방 코드는 비밀번호가 아니라 "같은 방에 들어가기 위한 식별자"입니다. 같은 네트워크의 다른 사람이 방 코드를 알면 해당 통화를 모니터링할 수 있으므로, 실험용으로만 짧게 사용하고 재사용하지 않는 것을 권장합니다.
- 실험 중 "내 발화 직접 입력"이나 공격자 대사 입력란에는 실제 타인의 개인정보(진짜 주민등록번호, 계좌번호 등)를 입력하지 마세요. 감지 테스트는 임의의 숫자로도 충분합니다.
- `server/logs/`에 쌓이는 세션 로그에는 테스트 중 발화된 텍스트가 그대로 기록됩니다. 실험 참가자의 실제 개인정보가 섞이지 않도록 주의하고, 로그를 외부와 공유할 때는 내용을 먼저 검토하세요.
